Scope: the whole program after the desktop window was added: function
tests against a running LightCraft 0.21.1 (throwaway libraries built from
catalog copies), performance, and a code review. State before the audit:
tag `pre-audit-2026-11-16`.

Status: function tests done; code review done for the reader, the model
and the window; **the review of the writer and the core was started but
not completed** (#45). Fixes are on the branches `js/timing`,
`js/gui-feedback` and `js/audit-fixes` (pull requests #41, #42 and the one
for this document). GitHub Actions did not start jobs during the audit
(account billing limit), so everything below was verified locally on
macOS only.

## Performance

`--apply` of 752 photos with real files (LightCraft 0.21.1, Apple M4 Pro):

| | Before | After |
| --- | --- | --- |
| Whole run | 111 s | 47 s |
| Commands sent | 5,187 | 4,447 |
| Time inside LightCraft | 74 s | 42 s |
| `library.import` | 752 single, 36 s | 12 batches, 4.6 s |
| Outside LightCraft (mostly saving the mapping file) | 37 s | 5 s |

Changes: imports in batches of 64 from 100 photos on; the mapping file is
saved at once only for records a later run cannot find again, otherwise at
most once a second and on every exit. All 752 LightCraft ids were checked
against their file names. Still open: 1,270 `library.select` commands
(about 10 s) could be saved (see #45 and the notes for the next step).

A run of the small test catalog (8 photos, 138 commands) takes 1.3 s. One
entry per photo, field, keyword and album is by design, so a catalog has
many more log entries than photos; the report and the window now count
photos separately (`photo_counts`).

## Findings and fixes

Severity: high = wrong or misleading result, medium = wrong in rarer cases
or a noticeable cost, low = small.

### First hand test (owner)

| Finding | Fix |
| --- | --- |
| Selected tab not visible enough | filled background |
| Target library empty although LightCraft was connected; no way back to LightCraft's library; no way to create a library | target follows LightCraft's open library; “Use library open in LightCraft”; “Open the chosen library in LightCraft”; “Create new…” with a confirmation |
| Catalog checks unexplained | “i” mark with an explanation on each |
| Log numbers do not match the number of photos | `photo_counts` (each photo once) first; entries labelled as such; group by photo |

| Transfer slow | see Performance |
| Stop and Cancel (with rollback) while running | **open**, next step |

### Window (code review)

| Sev. | Finding | Fix |
| --- | --- | --- |
| high | Finished-transfer screen parsed the whole report every frame | parsed once on the worker |
| high | A stopped or refused transfer was shown as “finished, 100 %”; the reason was shown nowhere | real progress kept, “Transfer stopped”, reason on the screen and as a log entry |
| high | The catalog scan was kept as full JSON and walked twice per frame | reduced to a small summary on the scan thread |
| medium | Log filters, groups and counts recomputed several times per frame | cached; recomputed when report, filters or grouping change |
| medium | End of a run parsed the report twice and wrote the history on the UI thread | parsed and written off the UI thread |
| medium | Start buttons enabled while LightCraft switches libraries | blocked |
| medium | A failed “Create library” overwrote a deliberately chosen library | followed only after success |
| medium | A probe answer from the old port was applied after a port change | answers carry their port |
| medium | Every keystroke in a mapping row started a full scan | scan waits half a second; a superseded scan is cancelled |
| medium | A background thread that died left the window waiting forever | reported as a failed result |
| medium | Run history grew without bound; index not written atomically | newest 50 runs kept; written beside and renamed |
| medium | Numbers of the previous catalog stayed when the new settings were incomplete | cleared when the settings change |
| medium | Spinner repainted at full rate | 20 frames a second |
| medium | Keyboard selection in the Log could leave the visible part | scrolled into view |
| low | “Read LightCraft library: done” shown when it was not needed | fixed |
| low | accessibility of painted labels, history delete, settings growth, dead code | #45 |
